# CLAUDE.md — Polypode Data (Addon WoW)

Addon compagnon de **Polypode** (dossier voisin `../Polypode`, dépôt séparé) : fenêtre « Données
des personnages » (données durables de chaque personnage, façon DataStore / WoWthing). Les
conventions de Polypode s'appliquent (voir `../Polypode/CLAUDE.md`) : commentaires en français,
code en anglais, pas de librairie externe, pas de `print()`, bloc `-- Polypode Data: Fichier —
rôle` en tête de fichier, tout contenu de taille variable défile, Retail (120000) et WoW Forever
(16001) avec tests d'existence des API (lectures sous `pcall`). Rester **simple** : on n'ajoute une
donnée que si elle sert à gérer ses personnages.

## Architecture

| Fichier | Rôle |
|---|---|
| `Polypode_Data.toc` | Data.lua, Deposit.lua, UI.lua ; `## Dependencies: Polypode`, SavedVariables de compte `PolypodeDataDB` (`chars`, `window`) |
| `Data.lua` | Relevé du personnage joué par section (`READERS`) : `I` identité (`c` classe, `r` race, `l` niveau, `i` ilvl équipé, `s` spé, `f` faction, `g` cuivre, `z` zone, `p`/`pa` temps de jeu et date du relevé), `T` métiers (`GetProfessions` → `p1 p2 s1 s2 s3` = « skillLine/niveau/max/icône/nom »), `E` équipement (`<slot>` = « ilvl@chaîne d'objet » du lien — `itemID:enchant:gemmes...:bonus` sans `item:`, les « : » passent dans le dernier champ du message ; ancien format « itemID-ilvl » encore lu par `EquippedItem`), `B` sacs / `K` banque / `A` banque de bataillon (`i<itemID>` = nombre ; sacs classés par nom dans `Enum.BagIndex` via `BagKind` ; `K` et `A` seulement banque ouverte, `BANKFRAME_OPENED`/`CLOSED`), `G` banque de guilde (`n` guilde, `m` or, `i<itemID>` ; ouverte = `PLAYER_INTERACTION_MANAGER_FRAME_SHOW`/`HIDE` de type `GuildBanker` → `OpenGuildBank` demande tous les onglets visibles par `QueryGuildBankTab`, `ScanGuildTabs` relit à chaque `GUILDBANKBAGSLOTS_CHANGED` (tout de suite : seul l'onglet affiché reste lisible ; cache par onglet `ns.GetGuildTabItems`), `ns.ReadGuildBank` = nil tant qu'aucun onglet n'est lu) ; `I.gu` = guilde du personnage. `Update` (2 s après un événement, `ScheduleUpdate` ; **jamais à `PLAYER_LOGOUT`** ni entre `PLAYER_LEAVING_WORLD` et `PLAYER_ENTERING_WORLD` (`leavingWorld` : le jeu ferme alors ses fenêtres — métier, banque — dont les fermetures déclenchent un relevé direct ; garde-fou `Suspicious` : un relevé vide de E / B / T, ou un niveau 0, ne remplace pas un relevé non vide) : sacs, équipement, métiers et `GetMoney` y sont déjà vides et écraseraient la sauvegarde — seul `seen` y est mis à jour) : section changée (texte comparé à `lastText`) → nouvelle version (`NextVersion`, heure serveur croissante), envoi 10 s après (`Push`). Sauvegarde `PolypodeDataDB.chars[clé] = { s, t, seen }`. Synchro : `DATAV:token:clé:S=version,...` à chaque HELLO/HI (`P.RegisterPeerCallback`), `DATAREQ:token:clé:S,S` pour les sections plus récentes, `DATA:token:clé:section:flag:version:k=v,...` (flag `N`/`+`, fragmenté ; `N` ignoré s'il n'est pas plus récent, `+` seulement pour la version commencée ; expéditeur vérifié par `P.IsSender`, le personnage joué fait foi pour lui-même). Temps de jeu : `RequestTimePlayed` à `PLAYER_LOGIN`, affichage coupé en court-circuitant `ChatFrameUtil.DisplayTimePlayed` le temps de la réponse (comme WoWthing). Enregistré auprès de `P.RegisterCharacterData` (suppression d'un personnage dans Polypode → `ns.Forget`, sur tous les clients). Banques partagées : `A` porte `a` = compte (token) ; `ns.AccountOf`, `ns.SharedOwner(clé, section)` (compte `a` ou d'après le roster / guilde `n`), `KeepNewestShared` garde une seule copie par propriétaire (la plus récente ; appelé au relevé, à la réception d'un fragment et au chargement par `KeepNewestSharedAll`, la version des copies effacées restant notée) ; `ReadContainers` renvoie nil sans emplacement lisible (banque pas chargée) ; `ns.ResetSection(section)` (remise à zéro : `B`/`K` du personnage joué, `A`/`G` toutes les copies de son compte / sa guilde, `lastText` effacé, sacs relus aussitôt). Section `R` recettes (`ReadRecipes` : fenêtre du métier ouverte `tradeSkillOpen` — `TRADE_SKILL_SHOW` / `CLOSE` / `LIST_UPDATE` / `DATA_SOURCE_CHANGED` —, pas lien / guilde / commande PNJ / forge runique ; `C_TradeSkillUI.GetBaseProfessionInfo`, `GetAllRecipeIDs`, `GetRecipeInfo(id).learned`, `GetProfessionInfoByRecipeID` → `r<recipeID>` = métier d'extension, `c<métier d'extension>` = « base/extension » ; métiers d'extension relus remplacés, les autres gardés). `T` : `g<p1...>` = emplacements des objets du métier (`GetProfessionInfoBySkillLineID` + `GetProfessionSlots`) ; `E` : emplacements 1-19 + `GetProfessionInventorySlots`. API interne `ns.GetEntry`, `ns.GetKeys`, `ns.Forget`, `ns.Clean`, `ns.SECTIONS` |
| `Deposit.lua` | Rangement automatique (bouton « Ranger » de la fiche Dépôts) dans la banque du personnage `K`, la banque de bataillon `A` ou la banque de guilde `G` (seule ouverte). Guilde : onglets `GetGuildBankTabInfo` visibles avec `canDeposit` (`GuildTabs`, `CanDepositInGuild`), contenu d'un onglet = lecture directe + `ns.GetGuildTabItems` (`GuildTabItems`), onglets contenant l'objet d'abord (`GuildCandidateTabs`) ; avant de déposer, l'onglet devient courant (`SetCurrentGuildBankTab` + `QueryGuildBankTab`, `run.guildFresh`) et on attend `GUILDBANKBAGSLOTS_CHANGED` (`run.guildWait`, 3 s max), de même après chaque dépôt (`PickupGuildBankItem`) ; pas de place pour un objet dans un onglet → `run.fullTabs["itemID:onglet"]`, onglet suivant. Placement commun `PickSlot` (pile incomplète, libre du même groupe, premier libre) ; banque sans place pour un objet : il reste dans les sacs, `run.full[kind]` pour le message final, les suivants continuent. `ns.OpenBanks` : `A` seule si PNJ `AccountBanker` sans `Banker` ni `CharacterBanker` (`C_PlayerInteractionManager.IsInteractingWithNpcOfType`) ; sinon (banquier, fenêtre de Blizzard ou Baganator...) → `K` et `A` quel que soit l'onglet affiché ; `G` = banque de guilde (`ns.IsBankOpen`/`ns.IsGuildBankOpen`/`ns.BagIDs` exportés par Data.lua). `ns.CanDeposit()` : faux (avec raison) si guilde ouverte avec `K`/`A`, sans droit de dépôt en guilde, ou aucune banque. `ns.StartDeposit()` : file des piles des sacs dont l'objet est déjà dans une banque ouverte (relue en direct), destination par entrée (`kind`, ordre `KINDS` = `K` puis `A`, `C_Bank.IsItemAllowedInBankType` pour `K`/`A` ; guilde : `isBound` et `C_Item.IsItemBindToAccountUntilEquip` écartés, comme Baganator, car `IsItemAllowedInBankType(Guild)` refuse tout), puis `Step` toutes les 0,1 s : attend curseur vide et pile déverrouillée, `FindTarget(kind)` (pile incomplète du même objet → `SplitContainerItem` si besoin ; sinon emplacement libre d'un onglet contenant l'objet ; sinon premier libre ; aucun = `run.full[kind]`, l'objet reste dans les sacs), prise puis pose (`PickupContainerItem`, `ClearCursor` si refusé). Arrêt : fin, banque fermée / changée, `ns.StopDeposit`. Avancement `ns.GetDepositStatus`, affichage par `ns.UpdateDepositControls` (UI.lua) |
| `UI.lua` | Fenêtre `PolypodeDataFrame` (`P.ToggleData`, `P.RefreshData` = `ns.Refresh`, `P.ui.dataFrame` / `dataPanel` / `dataSearchBox`), redimensionnable (taille dans `PolypodeDataDB.window`), titre à gauche, champ `SearchBoxTemplate` à droite. Tableau sans trait (même mécanique que Polypode Suivi : ligne d'en-tête `{ columnHeader, cells, tips }`, `COLUMNS` { en-tête, cellule(clé), tip, align (défaut RIGHT ; Métiers LEFT) }, largeurs mesurées dans `columnWidths`, `LayoutCells` de gauche à droite depuis `COLUMNS_START` (40 %) de la largeur de la fenêtre (`ColumnsStart`, recollées au bord droit si trop étroite ; relayout regroupé sur `OnSizeChanged`), `CellHover` pour l'infobulle des en-têtes) : Niveau, iLvl, Métiers, Or, Hauts faits (`I.ap` = `CharacterAchievementPoints` : somme des hauts faits « gagnés par moi » de `GetAchievementInfo`, chaînes par `GetPreviousAchievement`, guilde exclue ; en cache, recalculé à la connexion et à `ACHIEVEMENT_EARNED` — pas `GetTotalAchievementPoints`, qui est le total du bataillon), Temps de jeu (`PlayedSeconds` : relevé + temps connecté jusqu'à `seen`), Vu. Fiche d'un métier `OpenProfessionCard(clé, p1...)` → `ProfessionEntries` (objets de métier depuis `E` et `Professions().gear`, recettes de `R` par métier d'extension, `expandedTiers` repliables, la plus récente en tête, noms / icônes par `C_Spell` — `SpellName` demande les absents, `SPELL_DATA_LOAD_RESULT` rafraîchit —, clic `ShowSpell`). Détail `CharacterEntries(clé, sansÉquipement)` (métiers cliquables : `detail` à gauche, `rightDetail` à droite par la zone `row.rightButton` de la fiche) (métiers deux par ligne : champ `right`, infobulle en `{ gauche, droite }` si `P.LIST_TOOLTIP_COLUMNS`, fiche : colonne de droite par `decorate`) (entrées `{ text, detail, hint }`, marque « » » si `detail`) : infobulle `CharacterTooltip` ; clic gauche → fiche épinglée `OpenCard(titre, build, vide, action, gearKey)` (personnage : `gearKey` = sa clé, une seule fiche par personnage — déjà ouverte, elle est ramenée au premier plan — → équipement en icônes `FillGear` / `EnsureGear` / `CreateGearButton` : `GEAR_LEFT` / `GEAR_RIGHT` / `GEAR_BOTTOM` comme la fenêtre de personnage, bordure de qualité `WhiteIconFrame`, niveau d'objet, emplacement vide `C_PaperDollInfo.GetInventorySlotInfo`, infobulle `SetHyperlink`, clic `ShowItem` ; la liste des autres lignes entre les colonnes, sans l'équipement) (cadres réutilisés `cards`, `CreateCard` : déplaçable par glisser, croix `CloseButton` pour fermer, liste `P.CreateScrollList` ; clic (gauche ou droit) sur une ligne = `detail()` : `ContainerEntries` des sacs / banques dans une autre fiche, ou `ShowItem` → `SetItemRef` du lien complet ; sous chaque pièce, `ItemEnhancements(lien)` : enchantement et niveau d'amélioration lus dans `C_TooltipInfo.GetHyperlink` (motifs `FormatPattern` de `ENCHANTED_TOOLTIP_LINE` / `ITEM_UPGRADE_TOOLTIP_FORMAT_STRING`, textes secrets ignorés), gemmes par `C_Item.GetItemGem` ; `RefreshCards` à chaque `ns.Refresh`, `namesPending` remis à zéro au début) ; clic droit → `MenuUtil.CreateContextMenu` « Oublier ce personnage ». Recherche de recettes (`recipeBox`, `P.ui.dataRecipeBox`, à droite du champ des objets, `SEARCH_WIDTH` (105) chacun, `MIN_WIDTH` 640, une seule recherche à la fois : taper dans un champ vide l'autre ; `IsRecipeSearching`, `SearchRecipes` : section `R` de tous les personnages, nom par `SpellName`, résultats `{ recipe = { id, name, holders = { key, label } } }`, `RecipeRightText`, `RecipeTooltip`, clic `ShowSpell`). Recherche (`SearchItems`, dès 2 lettres, `Normalize` sans accents) sur B, K, E, la banque de bataillon la plus récente par compte (`WarbandBanks`, compte = `P.db.roster[clé].token`) et la banque de guilde la plus récente par guilde (`GuildBanks`, détenteur `guild:<nom>`) ; noms inconnus demandés (`C_Item.RequestLoadItemDataByID`), `ITEM_DATA_LOAD_RESULT` relance la recherche. Bouton « Ranger » de l'en-tête (`rangerButton`, `P.ui.dataRangerButton`, entre « Dépôts » et les icônes) : même `DEPOSIT_ACTION` que la fiche Dépôts (`update` avec `NO_STATUS`, relu toutes les 0,25 s par `OnUpdate` et par `ns.UpdateDepositControls`, infobulle `ShowDepositTooltip` → `ShowActionTooltip` commun avec la fiche : titre jaune, `summary` bleu clair, texte blanc ou rouge si `error`). Icônes du personnage joué à droite de « Ranger » (icônes `CONTAINER_ICON_SIZE` de `OWN_CONTAINERS` : Sacs `B` `INV_Misc_Bag_08`, Banque `K` `INV_Misc_Coin_02`, Bataillon `A` de son compte atlas `warbands-icon`, Guilde `G` de sa guilde `achievement_guildperk_mobilebanking` ; non skinnées ; `P.ui.dataContainerButtons`) : `OwnContainer(code)` → `{ title, data, version, missing }` (mêmes sources que `CharacterEntries` : `Sections`, `WarbandBanks`, `GuildBanks`), infobulle `OwnContainerTooltip` (`ContainerCount` : objets et différents, or de guilde, date du relevé), clic `OpenOwnContainer` → `OpenCard` de `ContainerEntries`, clic droit `ShowOwnContainerMenu` → « Remettre à zéro » (`ns.ResetSection`, message `REOPEN_HINT`) ; titre de la fenêtre borné par le champ de recherche (tronqué). Bouton « Dépôts » `P.ui.dataDepositButton` (à gauche du titre) → `ToggleDeposits` : fiche `OpenCard` de `DepositEntries` (par personnage, objets de `B` présents dans `K`, la banque de bataillon de son compte ou la banque de guilde de `I.gu` ; `OpenCard(titre, build, texteVide, action)` renvoie la fiche ; `action` = bouton à gauche de la croix + ligne d'état, `{ update, onClick, tooltip }`, relu 4 fois par seconde et par `UpdateCardAction` ; fiche Dépôts : `DEPOSIT_ACTION` « Ranger » / « Arrêter », grisé avec infobulle de la raison). Bouton `P.AddTitleButton` « Data » (`P.ui.dataButton` ; aussi dans la colonne de la barre flottante de Polypode ; `rightClick` : clic droit = `DEPOSIT_ACTION.onClick`, raison de `ns.CanDeposit` affichée si impossible), commande `/poly data` |

`P.WhisperOnline`, `P.IsSender`, `P.MAX_MESSAGE_LENGTH`, `P.GetTeamToken`, `P.GetCharKey`,

`P.SetListData`, `P.SkinFrame`, `P.SkinPanel`.
